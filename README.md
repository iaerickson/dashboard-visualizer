# dashboard-visualizer

A living desktop widget system for seeing ClaudeSpace project status at a glance — real widgets sitting on the desktop itself, not a page you have to remember to open.

**Status:** Active
**Category:** Claude Automations & Workflows (overlaps Creative & Design)
**Started:** 2026-07-30
**Moved to `Projects/` 2026-07-31** — it's real code now, not just a plan; matches the same convention `dj-library-manager` moved under.

## Goal

A visual home base that shows what's happening across the tracker — project status pulled from `INDEX.md`, how much is waiting on Ian, what got touched most recently — with good design and, eventually, real motion, not just a plain table. Should feel good to glance at, not just be informative. Ian explicitly wants this built the right way: proper planning, incremental phases, taste/polish reviewed at each step rather than rushed to a "final" version.

**Expanded vision (2026-07-31, per Ian):** this isn't meant to stay a read-only status card. The end goal is an "interface layer" — something that calls `log-pose`/`time-assessor`/`project-tracker` to actually help update and organize projects, not just display their state, and that Ian can keep adding to over time: new things to track, visualize, or interact with, for fun as much as for utility. Phase 1 (below) is the read-only foundation this grows out of, not the ceiling.

**Real fork worth flagging now, before building toward it:** "calls log-pose/time-assessor" can mean two very different things architecturally —
1. **Free, deferred pattern (matches everything else in this workspace):** the widget writes a request (e.g., a flag file, or an entry in `NEEDS-IAN.md`) that a Claude session picks up and acts on next time it runs — same shape as the existing scheduled tasks. No new cost, no new risk.
2. **Live, on-click LLM calls from the widget itself:** the widget directly calls the Anthropic API to run something log-pose-like in real time. Technically possible, but this means real, metered, per-call cost — which runs straight into the Ground Rules in `PROCESS.md` ("no spend without a green light," "avoid unexpected-cost exposure entirely, not just unapproved spend"). This would need real precautions (rate limits, a hard cap) in place *first*, and Ian's explicit sign-off, before any code gets written toward it.

Not deciding this unilaterally — flagged in `NEEDS-IAN.md`. Phase 1 doesn't touch this question either way since it's pure file-reading, no LLM calls.

## Setup

**Platform decided (2026-07-31): [Übersicht](https://tracesof.net/uebersicht/)** — a free, open-source (GPL-3) macOS app that renders HTML/JSX widgets directly on the desktop, behind icons and above the wallpaper. Confirmed via its own site and GitHub docs before committing to this: widgets are plain JSX files (`command` to run a shell command, `render` to draw the result, `refreshFrequency` for how often it re-runs), Übersicht watches the widget folder and live-reloads on change, and it's a well-established tool (4.9k GitHub stars) rather than something obscure or risky. No cost, no account, no data leaves your machine.

**To run the current widget (one-time setup, via symlink — no more manual re-copying on future edits):**
1. Download Übersicht from https://tracesof.net/uebersicht/ (free) and install it, if not already done.
2. If you'd previously copy-pasted the `claudespace-status` folder into Übersicht's widgets folder, delete that copy first (Finder: `~/Library/Application Support/Übersicht/widgets/`, or Übersicht's menu bar icon → "Show widgets folder").
3. Open Terminal (Spotlight → type "Terminal") and paste this one command, then hit enter:
   ```
   ln -s "/Users/ianerickson/Desktop/Projects/dashboard-visualizer/widgets/claudespace-status" "/Users/ianerickson/Library/Application Support/Übersicht/widgets/claudespace-status"
   ```
4. That creates a symlink — the widgets folder now points directly at the real files in this repo instead of holding a separate copy. Any future edit Claude makes here should show up automatically, no copying, ever again.
5. Quick way to confirm it worked: ask Claude to make a small visible tweak (e.g. change a label) and watch the desktop card — it should update within the 20s refresh without you touching Finder.

Requires Python 3 (already on macOS) — no other dependencies for Phase 1. Honest caveat on the symlink: this is standard macOS behavior for file-watching apps in general, but not something confirmed specifically against Übersicht's own watcher — if step 5 doesn't work, the fallback is quitting and reopening Übersicht once after an edit, which is still less friction than a full copy-paste each time.

**Verification script (2026-07-31, `automation-scout` finding):** `scripts/verify_widget.sh [path-to-ClaudeSpace]` bundles the two checks every round of live editing needed by hand this session — does `widgets/claudespace-status/index.jsx` still parse cleanly, does `scripts/status_summary.py` still run clean — into one command, read-only, exits non-zero on failure.

**Diagnosed symlink issue (2026-07-31):** Ian reported the widgets folder shows a `claudespace-status` entry that, when opened, contains "index and a shortcut to claudespace dir" — that's the signature of a Finder **alias** (made via Cmd+L or "Make Alias"), not a real Unix symlink from `ln -s`. Übersicht is a Node/Cocoa app that watches the filesystem directly; it very likely doesn't resolve a Finder alias the same way it resolves a true symlink, so it's probably still reading old/empty content — which matches "still shows the same previous active/idea/paused, only lists numbers." Fixed via `rm -rf` + `ln -s` redo, confirmed real symlink via `ls -la` (`claudespace-status -> .../dashboard-visualizer/widgets/claudespace-status`).

**Real bug found after the symlink fix (2026-07-31):** widget still didn't render — Übersicht's debug console showed `TypeError: (0, _uebersicht.keyframes) is not a function`. The `"uebersicht"` module only exports `css`/`styled` from its bundled Emotion, **not** a `keyframes` helper — the Phase 2 aesthetic-pass code imported and called it anyway, which threw at module load and killed the whole widget silently (no visible error on the desktop, only in Übersicht's own debug console — worth checking that console directly next time something goes blank). Fixed: dropped the `keyframes` import, folded both `@keyframes` blocks as literal, nested at-rules directly into `card`'s `css` template (Emotion hoists nested `@keyframes` to the global stylesheet under their literal name without needing the helper), and switched `animation: ${fadeIn}` / `${scan}` references to plain `animation: fadeIn` / `animation: scan`.

**Stale bundle cache, then a second real bug (2026-07-31):** after that fix, the exact same old error kept repeating in the debug console — turned out Übersicht's bundler was serving a cached build that predated the fix (fixed by quitting Übersicht and clearing its widget bundler cache). Once it was reading the live file, a second real bug surfaced: `Can't find variable: React`. Übersicht's JSX transform doesn't put a global `React` in scope, so the shorthand fragment syntax (`<>...</>`) used three times in `ProjectRow`'s tooltip — which compiles to `React.Fragment` under the hood — threw. Fixed by swapping all three for plain `<div>` wrappers, which don't need any global. **Lesson for future widget edits:** avoid `<>...</>` shorthand entirely in this codebase; use a real element (`<div>`, `<span>`) as the wrapper instead.
